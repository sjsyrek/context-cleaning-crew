# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Changed

- **Plugin metadata matches the marketplace entry.** `plugin.json` now carries the author email and the same description as the `sjsyrek` marketplace listing, including the three modes and the `python3` requirement.

## [0.1.1] - 2026-11-21

### Changed

- **README: full mode is interactive, like quick mode.** A headless run can't apply approved settings edits; the README now says so for `full` as well.

## [0.1.0] - 2026-11-21

### Added

- **README: installation and known limitations.** How to install from the `sjsyrek` marketplace, and what the audit doesn't catch (opaque secrets in MCP arguments and in the current project's rules, copies of a home that point at the live setup, unmeasured hook output).
- **Other projects' settings** (`permissions.other_projects`): for each project in `~/.claude.json`'s `projects`, its `.claude/settings.json` and `settings.local.json` are secrets-scanned (file, key and type in `secrets`) and checked for permission posture per project, with the user's settings but never another project's. Each file gets only its path, rule counts per list and finding counts per kind; no rule text, because redaction is pattern-only and an opaque secret in a rule would pass it. These files never feed enable flags, hooks, options or the current settings, and nothing is run.
- **Known projects in the manifest** (`projects`): the working trees in `~/.claude.json`'s `projects`, as `~/…` paths, so the reviewer can spot a CLAUDE.md in a directory above several of them (such as `~/Code/CLAUDE.md`), which loads in those projects only.
- **Executor helpers** (`scripts/executor.py`): `backup` copies the files a plan touches to `<backup_dir>/<stamp>/`, mirroring their paths under home, and snapshots `enabledPlugins` from each settings file. It refuses a temporary directory and files outside home, and never overwrites an existing backup. `restore-flags` puts back, after an uninstall, only the snapshot's enable flags for plugins the plan keeps, and leaves the file untouched when nothing is missing. The executor rules use both. A test replays the scope-aliasing accident from the manual cleanup on a copy of the `overlap` fixture and asserts the resulting tree.
- **Memory scope: duplicates and stray directories.** `memory.duplicates` groups user and feedback memories in different project directories that have the same body (ignoring case, whitespace and a final period) or the same `name:`, merging linked matches into one group with the projects it spans. `memory.stray_dirs` lists `<project>/.claude/memory` directories, which auto-memory never loads, for every project in `~/.claude.json` and every directory from home down to the working tree. New `memory` fixture.
- **Leftover state** (`leftovers`): an empty tracker directory (no files apart from OS litter such as `.DS_Store`) nearest the working tree is reported with the real tracker directory it shadows higher up, and the tracker's count entry marks `shadowed_by_empty`. The memory curator proposes removing it.
- **The reviewer judges what text means; the script never guesses.** The inventory enumerates, counts, compares versions, redacts and guards writes. Checklist lines in the quick-mode lenses and the context-economist and memory-curator seats cover what needs reading: instructions that contradict each other, one-off task procedures under a task heading, memory that reads as global, and a CLAUDE.md above several known projects. Hooks are listed and never run; the reviewer reads a context-injecting hook's script for output size and malformed JSON, and the report says hook output wasn't measured.
- **Plugin hooks.** Hooks shipped by installed plugins (`hooks/hooks.json`) are listed next to settings hooks, labeled `plugin <id>`.
- **MCP servers shipped by plugins** join the inventory, named `plugin_<plugin>_<server>` like their tool names, from each install's `.mcp.json` (wrapped or flat) and `plugin.json`. Each `mcp.duplicates` group now lists its `members` with their source (user config, local project entry, project `.mcp.json`, plugin) and a `keeper` with its `rule`: a protected server or plugin first, then a plugin server from the earliest preferred marketplace, otherwise `undecided`. `mcp.plugin_name_clashes` flags two plugins shipping a server under the same name. Plugin files aren't secrets-scanned; that scan covers the user's own config.
- **Scope aliasing and multi-scope plugins in the manifest.** `settings.scope_aliasing` says when the working directory is the home directory, so `~/.claude/settings.json` is both user and project settings, and carries the enable-flag warning. `plugins.multi_scope` lists every plugin installed at more than one scope with each install's project, and marks `shares_user_settings` when a project install is for the home directory. The overlap analyst and the executor use both. New `overlap` fixture.
- **Usage window and opt-in MCP usage** (`usage`): skills last used before the `usage_window_days` window are marked `unused`. With `mine_transcripts` on, the inventory counts MCP tool calls per server within the window from `~/.claude/projects/**/*.jsonl`, subagent transcripts included, and lists configured servers with no calls (`unused_servers`). Only assistant `tool_use` blocks count, so a tool name in a tool listing isn't a call. Tool inputs and per-tool names are never recorded. With the option off, no transcript is opened.
- **Keeper choice for duplicate plugins** (`overlap.plugin_duplicates`): a plugin installed from several marketplaces is grouped, with a deterministic `keeper` and the `rule` that picked it: a `protected` entry first, then the earliest `preferred_marketplaces` entry with a candidate. Otherwise it says `undecided`, which leaves the choice to the reviewer (capability, then usage). Protecting a bare plugin name protects every copy, and then nothing is picked. A new `protected` section resolves each entry to installed plugins, MCP servers and memory files, and lists entries that match nothing, so typos show up. Installed plugins carry a `protected` flag. The overlap analyst and the quick-mode lens use the manifest's keeper instead of choosing their own.
- **Plugin options** (`userConfig` in `plugin.json`): `preferred_marketplaces`, `protected`, `backup_dir`, `report_dir`, `usage_window_days`, `mine_transcripts`, `refresh_marketplaces`, `extra_secret_patterns` and `full_mode_models`. The inventory reads their values from `pluginConfigs` in the user's (and managed) settings, not from `${user_config.*}` substitution, which joins lists with commas and would corrupt regexes. It records the effective values, their sources and any ignored value in a new `options` section of the manifest. A wrongly typed value, an unknown key or an invalid regex falls back to the default with a warning (the warning never quotes the regex). `extra_secret_patterns` joins the secrets scan. New flags: `--mode quick|full|report` (quick and full refresh marketplaces and run trackers; report refreshes only when `refresh_marketplaces` is on and never runs trackers), `--save` (writes `<report_dir>/<yyyy-mm-dd>-manifest.json`) and `--options-settings`. `full_mode_models` is a single seat model because `userConfig` has no object type, and the synthesis always runs in the user's own session.
- **`context-cleaning-crew` skill, quick and report modes.** Runs the inventory, reviews the manifest through five lenses (context economist, overlap analyst, security reviewer, memory curator, workflow advocate), shows a numbered plan card grouped by category and applies only approved items in a fixed, backed-up order (`references/executor-rules.md`), then writes a dated report. Report mode changes nothing and ends with the same numbered card marked "proposed". Auditing a setup other than the live one (a backup, a copy) always runs read-only.
- **Full mode** (`agents/`, `references/full-mode.md`): five read-only seat subagents (context economist, overlap analyst, security reviewer, memory curator, workflow advocate) with `omitClaudeMd: true`, `Read`/`Grep`/`Glob` only and their own model and effort, dispatched in parallel without `name` (so they stay subagents even with agent teams enabled). After they return, the coordinator resumes the workflow advocate once by agent ID with the other seats' cuts, switches and moves. It answers with keep arguments and side effects, then the coordinator dedupes by target, resolves conflicts (usage-backed keeps win, security asks are never downgraded) and renumbers for the plan card. No agent teams are needed. Auditing another setup in full mode still runs the seats and applies nothing. New eval `04-full-mode` (Tier 2) passes 8/8.
- **Staleness facts in the manifest** (`facts`): tools named in memory files (multi-word command spans, or a name next to install/PATH wording) with whether each is on `PATH`, looked up and never executed; and the working tree's git remotes, read from `.git/config` (worktrees included) with credentials in URLs redacted. The memory curator checks memory claims against these instead of running commands.
- **Scheduled report runs** (`references/routine-setup.md`): a headless `claude -p` command with the minimal read-only allowlist under `--permission-mode dontAsk`, verified on a fixture copy (no permission denials, audited tree unchanged by checksum), wired to launchd and cron. The inventory takes `--out` (creating the report directory) so no shell redirect is needed, and `scripts/compare.py` prints a one-line summary (always-on token estimate, change since the last manifest, non-zero issue counts) that report mode ends with, for notifications.
- **Eval suite** (`evals/`) for `claude plugin eval`: report mode on a copied fixture home (finds the planted problems, no secret value in the output, no uninstall commands, audited tree unchanged by checksum), quick mode via a trigger phrase stopping at the plan card, and a should-not-fire case.
- **README** and MIT license.
- **Build plan** (`PLAN.md`): modes, inventory sources, review seats, plan card, executor order, configuration and the rules learned from a manual cleanup.
- **Inventory script** (`scripts/inventory.py`, Python 3.9+ standard library only): prints a stable, sorted JSON manifest with paths relative to `~`. This first slice covers settings files and reasoning-affecting env vars; permission posture (blanket `Bash` allow with `acceptEdits`/`bypassPermissions`, allow rules covered by a broader rule, rules that match no tool, MCP server or installed plugin); dangling and disabled plugin flags; CLAUDE.md and AGENTS.md files from `~/.claude` down through every parent of the working tree, with instructions that contradict a deny rule and procedural sections (five or more ordered steps) to move into a skill; references to removed tools in the user's own skills, agents and commands; memory directories with broken index links; and a plaintext-secret scan that reports file, key and token type, never the value.
- **Version drift, overlap and counts in the manifest.** Installed plugins are compared with their marketplace's version (`behind` / `ahead` / `current`, or `unknown` for remote sources), optionally after `claude plugin marketplace update` (`--refresh-marketplaces`); plugins that wrap a CLI are compared with its version (`bd --version` for beads); marketplaces with no installed plugins are flagged; plugins a built-in skill may replace (`/simplify`, `/code-review`, `/security-review`, `/loop`) are listed as candidates; and tracker counts name the command that includes closed items (`bd stats`, not `bd list`), running it only with `--run-trackers`.
- **Token cost, hooks, skill usage and MCP grouping in the manifest.** Each installed plugin's always-on and per-component on-invoke cost is parsed from `claude plugin details`; hooks are listed per event with the ones whose output is injected into context (`SessionStart`, `UserPromptSubmit`, `PreCompact`, `PostCompact`) marked; skill usage counts and last-used dates come from `~/.claude.json`; MCP servers with the same URL or command are grouped as duplicates and SSE transports are flagged. The marketplace refresh now runs before anything reads plugin state.
- **SessionStart update hook** (`hooks/hooks.json`, `scripts/update_check.py`): after a successful Claude Code update it prints one line suggesting `/context-cleaning-crew report`, once per new version, keeping the last seen version in `${CLAUDE_PLUGIN_DATA}`. On every other start (no update file, malformed file, failed update, version already seen, first run, unwritable state) it prints nothing and exits 0, so it costs no context.
- **Plugin manifest** (`.claude-plugin/plugin.json`).
- **Tests** (`tests/`, `unittest`) against a synthetic `messy` home fixture, plus `pyproject.toml` for the ruff and mypy dev checks.

### Changed

- **Quick and full mode are documented as interactive only.** A live headless quick-mode trial backed up the approved file and then had its settings edit refused: Claude Code protects `~/.claude/**` and a project's `.claude/settings*.json` from edits in `dontAsk` runs whatever the allow rules say. The executor stopped without working around it, as intended. The hash gate also lists two more Claude Code bookkeeping paths (`mcp-needs-auth-cache.json`, `plugins/.last_inuse_sweep`) and statusline tools' state.
- **The read-only hash gate lists every allowed path** (`PLAN.md`, "Read-only hash gate"): the plugin's own writes, the marketplace refresh including `known_marketplaces.json`, Claude Code's session bookkeeping, other plugins' hook state, and startup plugin auto-updates, which pass only when stamped before the run's first inventory call. `routine-setup.md` says what to expect when you hash `~/.claude` yourself.
- **Reports now go to `~/.local/state/context-cleaning-crew/reports/` by default** (the `report_dir` option), not `~/.claude/context-cleaning-crew/reports/`. Claude Code refuses Write-tool writes under `~/.claude` in a headless `dontAsk` run whatever the allow rules say (checked with six rule and directory variants), so a scheduled report run could save its manifest (written by the script) but never its report. The documented headless commands allow the new directory, and their `last-run.json` moves next to it. Existing reports stay where they are; set `report_dir` to keep the old place for interactive runs.
- **README states that `python3` must be on `PATH`**, since the skill and the SessionStart hook call it by name.
- **`PLAN.md` defines when step 8 (dogfooding) is done**: a table mapping each finding of the 2026-11-17 manual cleanup to the audit finding that catches it on a rebuild of the pre-cleanup setup (script, reviewer checklist, or not rebuildable from the backup), produced by a report run on a copy.
- **MCP servers whose URLs differ only in their query string now group as duplicates.** The grouping key is the masked target (see Security), so `https://host/v1?api_key=A` and `https://host/v1?api_key=B` are one `mcp.duplicates` group with target `https://host/v1?<redacted:query>`.
- **Memory duplicate grouping is plain dictionary lookups.** `memory.duplicates` groups personal memories by `name:` and by normalized body and merges groups that share a file, instead of comparing every pair through a union-find. The output is unchanged, including chains (a matches b by body, b matches c by name: one group).
- **The skill and seats take options from the manifest.** The inventory runs with `--mode <mode> --save`, so the mode's refresh and tracker rules and the `report_dir` option are applied by the script rather than restated in the skill. Seats read `options.values` and `protected` from the manifest instead of from the coordinator's prompt. Full mode passes `full_mode_models` as the Agent tool's `model` parameter on every seat spawn (omitted for `inherit`), so the option decides instead of the agent files' frontmatter. Eval `04-full-mode` checks it with a new `seats-model` grader. The executor backs up to the `backup_dir` option and never touches a protected item, and the report lists ignored option values and protected entries that match nothing. Auditing another setup always runs the inventory in report mode.

### Fixed

- **The skill runs its script commands on their own.** In a live headless report run the model chained `compare.py` with `grep` and `claude --version` in one Bash call, which the allowlist rightly denied as a whole; the skill now says to run each script alone and use Read, Grep and Glob for other checks.
- **Headless report runs no longer have the inventory command denied.** The skill ran `inventory.py --cwd "$PWD"`, and under `--permission-mode dontAsk` Claude Code 2.1.329 doesn't match a command containing a shell expansion against the `Bash(...)` allow rule. The skill now writes the working directory as a literal path, and a test keeps shell variables out of every command the skill and executor rules give Claude. Found by the live report-run gate.
- **`restore-flags` writes the settings file atomically** (a temporary file in the same directory, then `os.replace`), keeping the file's mode and writing through a symlink to its target, so a crash mid-write can't leave a truncated settings file.
- **`restore-flags` refuses a settings file outside home with a clear message and exit code 2**, including a settings path symlinked out of home. It used to crash with a bare `ValueError` traceback. Every other refusal (a file that isn't a JSON object, a snapshot without the file) now exits 2 the same way.
- **`restore-flags` refuses a snapshot that doesn't cover the settings file.** A snapshot without an entry for the file (or a missing snapshot) used to restore nothing and report success, so a lost flag went unnoticed. An entry holding `{}` (the file had no flags when it was backed up) is still valid and restores nothing.
- **`restore-flags` accepts an empty settings file.** A settings file holding `{}` (which an uninstall can leave behind) was refused as "not a JSON object", so the kept plugin's flag wasn't put back. A file that isn't a JSON object is still refused.
- **Auditing a backup or copy no longer writes your own home path into the manifest.** Hook commands and other paths pointing into the running user's home (not the audited one) now read `~` as well. Found by dogfooding on a rebuilt pre-cleanup setup.
- **Tracker counts run in the audited working tree.** With `--run-trackers`, `bd stats` ran in whatever directory the script was started from, so a `--cwd` elsewhere counted the wrong tracker.
- **Removed-tool references always name a replacement**, including the conditional TodoWrite/TaskCreate entries, so a review no longer invents one. A full-mode run had proposed rewriting a TodoWrite command for TaskCreate, which is gated by the same condition.
- **Git remote URLs never carry credentials into the manifest**, whatever the token format: the userinfo of a `scheme://` URL (`user:password@`, a bare token) and any query string are masked before the usual secret patterns run, including quoted git values and passwords containing `@`, `?`, `#` or spaces. Found by automated security reviews of the staleness facts.
- **Auditing another home no longer mixes in the live install's numbers.** `claude plugin details`, the marketplace refresh and CLI version probes always describe the live setup, so they are skipped when `--home` isn't the running user's home; the manifest records `live_setup`, and costs and CLI versions read "not checked: not the live setup". Found by the headless report run on a fixture copy, which reported a live plugin's token cost.
- **Absolute home paths no longer appear in free-text fields** such as hook commands; they are written as `~`, like every other path in the manifest. Found by a smoke run against a real setup.
- **No secret value reaches the manifest through free text.** Permission rule text, instruction-file lines, section headings and reasoning env values are now redacted (`<redacted:<type>>`), and the secrets scan also covers permission rules and every CLAUDE.md/AGENTS.md line. Extra patterns from `--secret-pattern` apply to both. Found by an automated security review of the first slice.

### Security

- **MCP server URLs never carry credentials into the manifest.** `mcp.duplicates[].target` goes through the same URL masking as git remotes: userinfo (`user:password@`, a bare token) and the query string are masked whatever the token format, for a server's `url` and for URLs in its command line. Before, only known token formats were redacted, so an opaque `?api_key=<uuid>` or password appeared verbatim when two servers shared the URL.
- **The executor's backup `--stamp` must be a plain directory name** (letters, digits, `.`, `_`, `-`, not starting with `.`). A stamp such as `../x` or `a/b` could put a backup outside the backup directory; it is now refused with exit code 2 before anything is written.
